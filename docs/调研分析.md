# standup 调研分析

> 调研日期:2026-08-29。结论基于当天的公开资料与开发机实际情况,后续如需引用请注意时效性。

## 一、竞品格局:桌面强、手机弱、两端不通

| 类型 | 代表 | 覆盖平台 | 主要短板 |
|------|------|----------|----------|
| 桌面开源 | [Stretchly](https://github.com/hovancik/stretchly) | Win / Mac / Linux | Electron 实现,内存占用约 200-400 MB;无手机端 |
| 桌面开源(老牌) | [Workrave](https://workrave.org/) | Win / Linux | 无 macOS 现行版本;无手机端 |
| 桌面开源(Mac) | [HealthTick](https://github.com/ruanyf/weekly/issues/9242) | macOS | 单平台 |
| 手机 App | [Anti-Sitting Timer](https://play.google.com/store/apps/details?id=net.west_hino.stop_suwarisugi)(Android)、MoveToZero(iOS) | 单手机端 | 与电脑状态完全不联动 |
| 轻量闭源 | [微软商店"久坐休息提醒"](https://apps.microsoft.com/detail/9n9tfrbprlxz) | Win | 功能极简 |

另:小米/华为手机在"运动健康"中自带久坐提醒,但只覆盖手机场景、不可定制、与电脑无关。

**结论 / 差异化机会**:现有工具要么只有桌面、要么只有手机,没有任何开源工具做到——
1. 电脑久坐到点提醒;
2. 用户在手机端活动时,电脑端自动感知并暂不催促;
3. 多端设置与统计数据互通。

## 二、各端能力与限制(动手前必须清楚)

| 平台 | 空闲/活动检测 | 后台能力 | 提醒形式 | 可行性结论 |
|------|--------------|----------|----------|-----------|
| Windows | ✅ 键鼠全局空闲检测 | ✅ 托盘常驻 | 通知 / 全屏遮罩 / 声音 | 能力齐全,首选 |
| macOS | ✅ 需辅助功能/输入监控权限 | ✅ 菜单栏 | 同上 | 与 Windows 共享大部分代码 |
| Linux | ⚠️ X11 完整、Wayland 受限 | ✅ 托盘 | 同上 | 跟随桌面端一并支持 |
| Android | ⚠️ 用屏幕亮起/步数等近似判断 | ⚠️ 前台服务 + 常驻通知;小米 HyperOS 等国产 ROM 需自启动 + 电池白名单,否则秒杀 | 通知 / 全屏 Intent | 可做,需专门处理后台管控 |
| **iOS** | ❌ 无后台活动感知 | ❌ 系统不允许后台常驻计时 | 仅固定时间表本地通知 | **已放弃**:只能做定时通知,无"感知久坐"的意义 |

## 三、技术选型对比

| 方案 | 运行内存 | 代码复用 | 移动端成熟度 | 结论 |
|------|---------|----------|--------------|------|
| **Tauri 2(选定)** | ~50-80 MB | 一套代码:桌面三端 + Android + iOS | 2024.10 起稳定;桌面端成熟,移动端稍年轻 | ✅ 核心逻辑用 Rust,前端复用 Web 技能 |
| Flutter | ~100-200 MB | 全平台一套 | 成熟 | 托盘、空闲检测依赖第三方插件;体积内存中等 |
| Electron | 200-400 MB | 仅桌面 | 无官方移动端 | ❌ 开发机 8 GB 内存常年占用 ~88%,Electron 不可接受 |
| 各端原生 | 最低 | 几乎为零 | — | 工作量 ×4,不符合"小工具"定位 |

**Tauri 2 的关键依据**:
- 安装包几 MB、运行内存约为 Electron 的零头,对 8 GB 内存的开发机是实打实的差别;
- 前端用 HTML/JS,与维护者现有 Web 技能(Astro 网站)同源;
- 桌面端生产可用性社区评价高;移动端(iOS 尤甚)边角问题多——正好我们已放弃 iOS,Android 排在 Phase 2 可规避大部分风险;
- 参考:[Tauri 2.0 稳定版发布公告](https://v2.tauri.app/blog/tauri-20/)、[移动端成熟度社区讨论](https://github.com/orgs/tauri-apps/discussions/10197)、[桌面端生产使用评价](https://www.reddit.com/r/tauri/comments/1s6xqem/how_is_tauri_for_building_production_desktop_apps/)。
