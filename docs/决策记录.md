# standup 决策记录(ADR 风格)

> 记录已拍板的决策与待确认事项。每条决策一经确认不再反复重议;如需推翻,在此追加新决策并注明理由。

## 背景与约束

- 开发机:Windows 11(26200),8 GB 内存且日常占用约 88%,C 盘剩余约 69 GB —— 排除 Electron 等高内存方案。
- 使用者设备:Windows 笔记本(RedmiBook 13)为主力工作设备 + 小米/红米手机;主力场景是"电脑前工作时被提醒"。
- 维护者前端技能可用(有 Astro 网站项目),Rust 部分代码量可控,可借助 AI 辅助开发。
- 项目定位:**小工具** —— 拒绝过度设计,能日常自用、可长期维护优先于功能大而全。

## 已确认的决策

### D1. 放弃 iOS 端 — ✅ 已拍板(2026-08-29)
iOS 系统不允许后台常驻计时,无法感知"用户坐了多久",只能按固定时间表发本地通知,与本工具"智能久坐感知"的定位不符,没有开发意义。文档中的 iOS 相关内容仅作背景留存。

### D2. 技术栈:Tauri 2 — ✅ 已拍板(2026-08-29)
Rust 核心 + Web 前端。理由:内存占用最低档(~50-80 MB)、桌面三端 + Android 同一代码库、复用维护者 Web 前端技能。对比依据见 [调研分析.md](调研分析.md) 第三节。

### D3. 架构原则:Rust 核心库 + 平台外壳 — ✅ 已拍板(2026-08-29)
久坐计时状态机(活动检测 → 累计久坐时长 → 到点提醒 → 休息完成重置)实现为**平台无关的纯 Rust crate**;各端外壳(Tauri 工程)只负责接入平台能力:键鼠空闲检测、通知、托盘、前台服务等。多端复用靠架构保证,不靠复制粘贴。

### D4. 平台路线:Windows → Android → macOS/Linux — ✅ 已拍板(2026-08-29)
- Phase 1:Windows 桌面端 MVP(主力场景,先自用)
- Phase 2:Android 端(前台服务 + 常驻通知,专门处理小米 HyperOS 后台管控;初期与 PC 端各自独立计时)
- Phase 3:macOS / Linux(同一 Tauri 代码基本免费获得);多端设置与统计的轻量同步(导出/局域网优先,不急于上云);Web 统计看板作为兜底端

### D5. 提醒基调:温和提醒,不做强制锁定 — 🔶 倾向已定,待讨论细化
默认通知提醒 + 可选全屏休息页;不做强制锁定键盘鼠标的激进模式(Workrave/AHK 类工具的做法)。具体交互细节在开发讨论中确定。

### D6. Phase 1 MVP 功能边界 — ✅ 已拍板(2026-08-29)
**进入 Phase 1**:托盘常驻、可配置久坐间隔、空闲检测自动暂停、到点提醒 + 可选休息页、本地统计(轻量版)。
- 休息页:默认置顶倒计时小窗,全屏遮罩做成设置开关、默认关(交互细节在"提醒交互"讨论中细化)。
- 本地统计:仅本地 JSONL 事件流水(每次提醒/休息各一行)+ 设置窗顶部"今日概览"一行;图表与历史页推迟到 Phase 2/3 统计看板。
**默认参数**:久坐间隔 45 min(可配 15–120);休息时长 5 min(可配 1–15);空闲阈值 5 min(可配 2–15)——空闲超过阈值视为"已自然休息",计时清零重计。
**明确不做**(Phase 1):统计图表/历史页、工作时段表、全屏应用检测、多语言(界面仅中文)、更新检查、数据导出/同步(多端同步见 D4 排期);开机自启归入工程细节讨论。
**验收闭环(唯一主链路)**:托盘常驻 → 连续久坐满间隔 → 温和提醒 →(可选)休息页倒计时 → 休息结束/跳过后计时清零;中途空闲超阈值计时清零。

### D7. 提醒交互细节 — ✅ 已拍板(2026-08-29)
- **提醒通道**:自绘"休息卡片"小窗——右下角、置顶、不抢焦点、3 分钟未响应自动淡出、无提示音;按钮「开始休息」(主)/「先不了」(次)。不集成系统通知插件:官方 tauri-plugin-notification 在 Windows 底层(winrt-notification)不支持按钮,且未安装运行的 exe 发通知会失败。
- **频率**:每个久坐间隔照常提醒,不升级、不重复;上一轮未响应不影响下一间隔照常触发。
- **默认文案**:标题"已经坐了 45 分钟啦",正文"起来活动一下吧,顺便看看远处"(随时可改)。
- **休息页**:大数字倒计时 + 轮换放松建议("看看 6 米外""伸展肩颈""喝口水"),倒计时结束自动关闭;默认右下角置顶小窗,全屏开关打开后为居中大倒计时(Phase 1 仅盖主显示器);深色柔和背景、无动画。
- **跳过规则**:前 30 秒仅显示倒计时,之后出现"提前结束"按钮。
- **完成判定**:关闭休息页 = 本次休息结束、久坐计时清零(提前结束亦清零);事件流水记实际休息时长。
- **勿扰**:不做配置化勿扰时段;托盘提供"暂停 1 小时 / 暂停到明天 / 恢复"。

### D8. 空闲检测实现(Windows)— ✅ 已拍板(2026-08-29)
- **方案**:`GetLastInputInfo` 每 1 秒轮询,官方 `windows` crate 直接调用,不引第三方空闲检测库;不用低级键鼠钩子。
- **判定模型**:外壳采样 `idle = now − lastInput`,向核心库发 `ActivityTick { idle_secs }`;`idle < 阈值` 为活动态、久坐累计继续(看视频/读文档也算久坐);`idle ≥ 阈值`(D6 默认 5 min)判定"离开",计时清零,流水记离开事件(带空闲时长),出现新输入后从零累计。
- **锁屏**:监听 `WTS_SESSION_LOCK`,锁屏立即清零计时;解锁后从零累计。
- **睡眠**:监听 `PBT_APMRESUMEAUTOMATIC`,唤醒即时将状态机置为"离开",避免唤醒瞬间误报超长久坐;睡眠期间进程冻结,无额外处理。
- **屏保/显示器关闭**:由空闲阈值自然覆盖,不单独处理。
- **事件挂载**:锁屏/电源事件挂 message-only window,不占用 Tauri 主窗口消息循环(细节进技术设计文档)。

### D9. 前端选型与 UI 风格 — ✅ 已拍板(2026-08-29)
- **框架**:Vue 3 + TypeScript + Vite(`create-tauri-app` 官方 vue-ts 模板);不引状态管理库,前端保持极薄(Tauri command + event + 渲染);Phase 2 Android 复用同一前端。备选原生 TS / React / Svelte 经比较后放弃(对比见讨论记录)。
- **样式**:Tailwind CSS(v4,CSS-first 配置),主题用 CSS 变量衔接深浅色。
- **视觉**:品牌化路线,三个窗口(设置窗、休息卡片、休息页)全部无边框自绘——需自行处理拖拽(`data-tauri-drag-region`)、最大化/还原、窗口贴边等细节;深浅色跟随系统,系统字体栈。
- **取舍说明**:自绘标题栏比系统标题栏多约 1–2 天工,是"好看"换来的已知成本;接受。

### D10. 工程细节:自启/托盘/配置/分发/命名/协议 — ✅ 已拍板(2026-08-29)
- **开机自启**:进 MVP,`tauri-plugin-autostart`,默认开、设置可关(注册表 Run 键,任务管理器"启动应用"可见可关)。
- **托盘**:左键单击打开设置主窗;右键菜单自上而下:状态项(灰显:"下次提醒 N 分钟后"/"已暂停至 xx:xx")→ 立即休息 → 暂停 1 小时 / 暂停到明天 / 恢复 → 设置… → 退出;tooltip 动态显示久坐时长;图标两态(正常/暂停灰化)。
- **配置与数据**:`%APPDATA%\standup\` 下 `config.json`(serde 序列化 + 默认值合并,可手动编辑)与 `events.jsonl`(统计事件流水)。
- **分发**:GitHub Releases 挂 NSIS 安装包为唯一 MVP 渠道;发布后顺手提交 winget 清单;不做微软商店;无代码签名(SmartScreen 提示"仍要运行",README 说明);仓库配 GitHub Actions 构建。
- **命名**:正式名 **StandUp**(仓库 standup,副标题"久坐提醒小工具"),应用标识 `io.github.<用户名>.standup`。
- **协议**:MIT OR Apache-2.0 双许可。

### D11. 全局主题(皮肤系统雏形) — ✅ 已拍板(2026-08-29)
维护者反馈"本体界面希望与遮罩风格一致,未来可增强为皮肤系统",据此修订 D9 的视觉方向:
- 原"休息页配色"升级为**全局主题**:在 `ui/src/style.css` 以 design tokens(CSS 变量,按 `[data-theme]` 分段)定义背景渐变、卡片、文字、强调色、进度环、光晕;设置窗、休息卡片、休息页三窗口统一消费变量,组件不写死颜色。
- 现有三套主题:夜航(深蓝,默认)、森野(深绿)、晨雾(浅色纸感)。深浅偏好通过选择主题表达;原"界面主题(跟随系统/浅色/深色)"开关移除,概念归一为"主题"。
- 选择 UI:设置窗顶部主题色卡(渐变色块),点击即改即存,经 `config-changed` 广播三窗口实时换肤。
- **未来扩展为完整皮肤系统**:新增皮肤 = style.css 增加一段 tokens + `SKINS` 常量加一项,无需改组件。

### D12. 常驻模式(空闲判定开关) — ✅ 已拍板(2026-08-30)
真机使用发现 D8"空闲超阈值即判离开并清零"的盲区:人坐在屏幕前阅读/看视频、长时间不碰键鼠,会被误判为离开、永不提醒。据此在原语义上增补:
- **常驻模式开关**(设置 → 通用,`resident_mode`,默认关):开启后 Tick 空闲判定整体旁路——Active 不因空闲转 Away,Away 状态直接回 Active,**按墙钟持续累计、到点必提醒**。
- **边界不变**:锁屏/睡眠仍强制 Away(物理离开证据确凿);手动暂停优先级不变;短空闲(低于阈值)本就不清零,D8 其余语义不变。
- **动机定位**:覆盖"阅读型在场"场景;默认仍关,标准输入检测是主流语义。

### D13. 跨端同步:WebDAV(用户自带网盘) — ✅ 已拍板(2026-08-30)
方案对比(手动导出 / 自建云服务 / WebDAV / 局域网直连)后选定 **WebDAV**:无需自建服务端,数据存用户自己的坚果云/Nextcloud,符合"小工具"定位与隐私预期。局域网直连(手机感知→电脑暂停催促)归 Phase 2。
- **同步内容**:配置(整体)+ 事件流水。同步设置本身(WebDAV 账号等)不参与同步——各端各配各的。
- **远端布局**:`<WebDAV地址>/standup/config.json`(信封 `{updated_at, config}`)、`/standup/events.jsonl`。
- **冲突规则**:配置按 `updated_at` 新者赢(整体采用,不做字段级合并;离线双端各改时后改者胜,老改动丢失);流水按 `t|at_ms` 并集去重合并,**永不丢数据**。
- **凭据安全**:WebDAV 应用密码只存系统凭证管理器(keyring:Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service),永不进明文文件、永不回传前端。
- **触发时机**:启动 10 秒首推 + 每 15 分钟 + 设置页「立即同步」;结果回写 `sync.json`(上次时间/成败/原因)。
- **界面重组**(修订 D9 的单列滚动):设置窗改为**四标签页**——概览(今日久坐 + 实时状态 + 立即休息/暂停快捷 + 开机自启)、提醒(三滑杆 + 常驻模式)、外观(主题 + 全屏遮罩)、同步(WebDAV 表单)。原「通用」分组语义归位:常驻模式属提醒行为,全屏遮罩属外观。
