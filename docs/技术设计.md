# StandUp 技术设计(Phase 1)

> 2026-08-29 经维护者确认。决策依据见 [决策记录.md](决策记录.md)(D1–D10)。

## 一、总体架构

三层,数据流单向:**外壳采样 → 事件喂给 core → core 输出指令/流水事件 → 外壳执行,前端只呈现**。

| 层 | 职责 | 明确不做 |
|---|---|---|
| `crates/standup-core`(纯 Rust) | 状态机、配置模型 + 默认值合并、流水事件模型、今日概览聚合;卡片淡出/休息倒计时/暂停恢复等定时判定全部在此,以输入时间戳驱动,无线程、无 IO | 不依赖 tauri / tokio / windows,可独立单测 |
| `src-tauri`(Tauri 外壳) | Win32 空闲采样与锁屏/电源事件、托盘、三窗口管理、`config.json` / `events.jsonl` 读写、command/event 桥、autostart 插件 | 不含业务判定逻辑 |
| `ui`(Vue 3 + Tailwind) | 三个独立 webview 入口,只做"调 command、听事件、渲染" | 无路由、无状态管理库 |

## 二、核心状态机

### 状态(4 个)

`Active`(久坐累计中)、`OnBreak`(休息页打开)、`Away`(离开:空闲超阈值 / 锁屏 / 睡眠)、`Paused`(手动暂停,带恢复时间点)。

### 输入事件(全部带毫秒时间戳,由外壳驱动 core 推进)

| 事件 | 来源 |
|---|---|
| `Tick { now_ms, idle_secs }` | 1 秒轮询 `GetLastInputInfo` |
| `SessionLock` / `SessionUnlock` | WTS 会话通知(message-only window) |
| `Suspend` / `Resume` | 电源事件 `WM_POWERBROADCAST` |
| `CardAction { StartBreak \| Dismiss }` | 休息卡片按钮(前端 command) |
| `BreakEnd { completed }` | 休息页关闭(倒计时自然走完或用户提前结束) |
| `PauseUntil { until_ms }` / `ResumeNow` | 托盘菜单 |
| `ConfigChanged(Box<Config>)` | 设置窗保存 |

### 输出

`ShowCard` / `HideCard`、`ShowBreak { fullscreen }` / `CloseBreak`、`Flow(FlowEvent)`(外壳追加写 `events.jsonl`)、`StateChanged`(刷新托盘 tooltip/图标与今日概览)。

### 关键转移规则

1. `Active` 且轮次累计 ≥ 久坐间隔 → **发提醒**(弹卡片),同时**轮次计时清零**——提醒即一轮终点,无论休不休息,每 45 分钟节奏不变(D7-F1,不升级不重复)。
2. `Active` 且 `idle ≥ 空闲阈值` → `Away`,记 away 流水,新输入后回 `Active` 从零累计(D6/D8)。
3. 任意状态 + 锁屏/睡眠 → 强制转 `Away`,并关闭卡片/休息页(锁屏型 away 事件 `idle_min` 记 0,表示未测量)。
4. 卡片「开始休息」→ `OnBreak`(倒计时 = 休息时长);`BreakEnd`(走完/提前)→ 回 `Active` 从零累计,流水记实际休息时长(D7)。`OnBreak` 期间空闲事件忽略,但锁屏仍强制 `Away`。
5. `Paused` 不累计不提醒、忽略锁屏/空闲;恢复时间到或手动恢复 → `Active` 从零累计(D7-N1)。
6. 卡片 3 分钟无动作自动淡出:仅 `HideCard`,无状态转移(D7)。

### 计时口径

今日久坐 = 各轮提醒时记录的 `seated_min` 之和 + 当前轮进行中累计;今日提醒 = reminder 事件数;今日休息 = break 事件数与实际时长合计。单次 Tick 的墙钟增量上限 2 秒,超过视为挂钟异常(挂起/休眠由专门事件处理),防止计时暴涨。

## 三、流水与配置

- `events.jsonl`(JSONL 追加写,`%APPDATA%\standup\`),事件 schema(`t` 为类型标签):
  - `{"t":"reminder","at_ms":…,"seated_min":45}`
  - `{"t":"break","at_ms":…,"planned_min":5,"actual_min":4,"completed":true}`
  - `{"t":"away","at_ms":…,"idle_min":0}`
- `config.json`(serde,`#[serde(default)]` 缺字段用默认):`reminder_interval_min=45`、`break_duration_min=5`、`idle_threshold_min=5`、`fullscreen_break=false`、`autostart=true`。

## 四、窗口清单(全部自绘无边框,D9)

| 窗口 | 形态 | 行为 |
|---|---|---|
| `main` 设置窗 | ~420×640,自绘标题栏 | 关闭 = 隐藏到托盘;退出走托盘菜单 |
| `card` 休息卡片 | 右下角 ~360×140,创建不抢焦点 | 由 core 指令显隐;按钮「开始休息」「先不了」 |
| `break` 休息页 | 默认右下角小窗;全屏开关打开后覆盖主显示器 | 前端负责流畅渲染倒计时,判定以 core `BreakEnd` 为准 |

## 五、目录结构

```
standup/
├─ docs/                      # 调研分析 / 决策记录 / 技术设计
├─ crates/standup-core/       # 纯 Rust 状态机 crate(workspace 成员)
│  └─ src/  lib.rs  state.rs  config.rs  events.rs
├─ src-tauri/                 # Tauri 外壳(Phase 1 Windows 实现)
│  ├─ src/  lib.rs  commands.rs  tray.rs  windows.rs  store.rs  driver.rs
│  │        platform/mod.rs  platform/win.rs
│  ├─ tauri.conf.json  capabilities/  icons/
├─ ui/                        # Vue 3 + Tailwind, Vite 多入口
│  ├─ index.html  card.html  break.html
│  └─ src/  settings/  card/  break/  shared/
├─ .github/workflows/release.yml
├─ LICENSE-MIT  LICENSE-APACHE  README.md
└─ Cargo.toml                 # workspace: crates/* + src-tauri
```

Rust 侧线程模型:tick 线程(1 秒采样)与 Win32 事件线程(message-only window)只向 channel 发 `Input`;driver 循环消费 `Input` → 推进 `Core` → 执行输出(窗口显隐、emit 前端事件、写流水、更新托盘)。托盘菜单与前端 command 同样汇入该 channel,状态机单线程推进,无锁竞争。
