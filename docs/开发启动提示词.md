# standup(久坐提醒小工具)开发启动讨论

你是与我协作的开发助手,工作目录是 `D:\dev\standup`。这是一个久坐提醒多端小工具项目,前期调研已完成,现在进入**开发讨论阶段**——只讨论设计,尚未开始写代码。

## 第一步:先读文档
请先完整阅读以下两份文档再开始讨论,不要跳过:
- `docs/调研分析.md` —— 竞品格局、各平台限制、技术选型对比
- `docs/决策记录.md` —— 已拍板的决策(D1-D5)和待确认假设

## 已确定的决策(不要重新讨论)
1. 技术栈:Tauri 2(Rust 核心 + Web 前端)
2. 端范围:Windows → Android → macOS / Linux;iOS 已明确放弃,不再提及
3. 架构:久坐计时状态机做成平台无关的纯 Rust 核心库,各端外壳只接平台能力
4. Phase 1 只做 Windows 桌面端;提醒基调是温和提醒,不做强制锁定键鼠

## 本次要讨论的问题(共 5 项,逐项进行)
1. **MVP 功能边界**:在"托盘常驻、可配置间隔、空闲检测自动暂停、通知 + 可选全屏休息页、本地统计"里划 Phase 1 的边界——哪些进、哪些砍、默认参数取什么值。宁可小而完整,不要大而半成品。
2. **提醒交互细节**:通知的文案与频率、全屏休息页的行为(倒计时时长、能否跳过、"休息完成"如何判定)、勿扰/免打扰时段要不要进 MVP。
3. **空闲检测实现**:Windows 下 GetLastInputInfo 等方案的取舍,"离开自动暂停"的判定阈值,锁屏/睡眠时的处理。
4. **前端选型**:Tauri 内的框架(原生 TS / Vue / React / Svelte)与 UI 风格,给出对比和推荐。
5. **工程细节**:开机自启、托盘交互、配置文件存放、打包分发渠道、项目正式命名与开源协议。

## 讨论规则
- 一次只讨论一项:先给可选方案对比和你的明确推荐(附理由),等我拍板后再进入下一项。
- 每项拍板后,把结论追加到 `docs/决策记录.md`(沿用现有格式编号 D6、D7…),保持文档与讨论同步。
- 5 项全部确认后:先输出一份简要技术设计文档(模块划分、核心状态机设计、目录结构)供我确认,**经我确认后才开始**创建项目骨架和代码。
- 现在从第 1 项开始。
